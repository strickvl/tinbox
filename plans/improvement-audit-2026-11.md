# Tinbox improvement audit (1 November 2026, v0.5.1)

Read-only audit of `src/tinbox` by three parallel reviewers (stability, refactoring, features), with the headline findings re-checked by hand. `just check` and `just test` both pass (755 tests, 93% coverage). Line numbers refer to the tree at commit 5f28944.

## A. Bugs that lose data or money (fix first)

1. **Checkpoint resume does not check it is the same document or the same chunking.** `checkpoint.py:74` keys the file by `input_file.stem`; `checkpoint.py:139-153` compares only languages, provider, algorithm, protocol and local flag. Reproduced: rerun with a different `--context-size` after a crash → output holds 21 of 60 sentences, no warning. Rerun on a different file with the same stem → output starts with the other document's translation. Fix: store a source SHA-256, `model_name`, `context_size`, `custom_split_token`, window sizes and chunk count in the checkpoint and refuse to resume on mismatch.
2. **Partial PDF failure exits 0 and deletes the checkpoint.** `cli.py:519-521` always cleans up; nothing sets a non-zero exit when `response.failed_pages` is non-empty. Reproduced with CliRunner: 3 pages, page 2 fails, exit 0, checkpoint dir empty. The user pays for all pages again to retry one. Fix: keep the checkpoint and exit non-zero when pages failed; print "rerun to retry pages …". Page mode already skips completed pages on resume, so retry-only-failed then works for free.
3. **One failed chunk in `context-aware` or `sliding-window` discards the whole run.** `algorithms.py:854/926` and `:464/523` re-raise; the CLI writes nothing. Checkpoints are off by default, so all paid work is lost. The `--max-cost` raises (`algorithms.py:302, 505, 903`) do the same. Fix: write partial output plus a failure marker, or save a final checkpoint in the `except` before raising.
4. **Quota-exhausted 429s are retried 10 times, about 6 minutes, per page.** `_shared.py:74-79` retries every `RateLimitError`, including `insufficient_quota`, with sleeps [4,4,4,8,16,32,64,120,120] on top of the SDK's own retries, and without `reraise=True` the final error reads `RetryError[<Future …>]`. A 100-page PDF with no credit takes ~10 hours to fail. Fix: do not retry quota or auth errors, abort the run on them, set `reraise=True`, honour `retry-after`.
5. **Pricing is per provider, not per model, and stale.** `cost.py:21-37` is "as of September 2025", priced as GPT-5 and Sonnet 4; `claude-opus-5-5` and `claude-haiku-5-5` both estimate the same. Final cost, progress-bar cost and `--max-cost` are all off by the real price ratio. Also: `--max-cost 0` disables the cap (`config.max_cost and …`), and the cap is checked only after each paid call. Fix: per-`model_name` table with a warning for unknown models, `--price-in/--price-out` override for custom endpoints, `is not None` check, pre-call projection.
6. **Billed-then-rejected calls never count toward cost.** `openai.py:232-266`, `anthropic.py:252-276`: bad finish reason or JSON parse failure raises before `calculate_usage_cost`. Fix: compute cost from `usage` first and attach it to the error.
7. **DOCX drops tables, headers, footers, footnotes.** `docx.py:57-61` reads `doc.paragraphs` only; reproduced. Paragraphs join with `\n` so the paragraph-break split rule never fires. Fix: walk the body in order including tables, join with `\n\n`, count tables in the estimate.
8. **Whole PDF rasterised into memory before the first call.** `pdf.py:160-170` converts all pages; 300 pages at 200 DPI ≈ 3.5 GB. Fix: rasterise one page at a time.

Smaller: Anthropic replies parsed with bare `json.loads`, no fence stripping (`_shared.py:273-276`); Markdown output wraps text in ```` ```text ```` without escaping inner fences (`output.py:144-146`); UTF-8 BOM passed to the model (`text.py:57`); empty PDF crashes with `list index out of range` (`processor/__init__.py:215`); `translate`'s `except Exception` at `cli.py:570` also catches `typer.Exit`, so `--to xx` prints "Translation failed" plus a traceback; `doctor` prints key prefixes and last 4 chars.

Test gaps: resume after changing `context_size` or with a same-stem file; exit code and checkpoint cleanup on partial failure; `RetryError`; fenced JSON; DOCX tables; the progress bar (no test touches `add_task`/`progress.update`).

## B. Refactorings (value / effort order)

1. **Delete dead code (tiny, ~150 src + 60 test lines).** `algorithms.TranslationProgress` (30-91, zero references); the unreachable `elif resume_result.translated_items` at `algorithms.py:199-202`; the `None` fallbacks for `window_size`/`overlap_size`/`context_size` (`algorithms.py:403-408, 763`, `cli.py:534`); `checkpoint.should_resume`/`load_checkpoint` (219-248, tests only); `progress.format_cost` (tests only); `TranslationConfig.progress_callback`, `.verbose`, `.force` (never read by core); `output.py:83-86`.
2. **One `_Run` helper in algorithms.py to replace three copies of the bookkeeping (medium, biggest win).** Request build, glossary update, token/cost/progress, `TranslationState` save, max-cost check, resume+glossary restore and outer exception wrap are copied in page (240-305), sliding (445-508) and context-aware (835-906). Also type `ResumeResult.metadata` (dict of Any) into fields. Expected 928 → ~650 lines, so no file split needed. Guarded by the existing algorithm tests, which assert `save.call_args_list` states. Must keep: per-algorithm `TranslationState` contents, 1-based frequency, page tolerates errors / others abort, progress advances only on success, progress task created before resume in page mode but after in the other two.
3. **Shrink cli.py with zero test churn (small).** Move `prepare_matches`, `annotate_review`, `review` (576-766) to `review_cli.py` and register with `app.command()(fn)`; 837 → ~645. Inside `translate`, extract `_resolve_algorithm`, `validate_review_export_paths` (to `core/review.py`), `_build_output`, `_save_review_bundle`, `display_translation_stats`, `_progress`. Do **not** move the orchestration into core yet: test_cli.py has 53 `patch("tinbox.cli.X")` sites that would all break; convert those tests to fake only `create_translator` first (as test_cli_review.py already does).
4. **Provider skeleton + table-driven doctor (medium).** `openai.translate` (204-285) and `anthropic.translate` (224-293) share the same steps; extract `_shared.run_translation(request, call, read)`. Prompt strings duplicated at `anthropic.py:147-151/171-174/128-138` and `openai.py:121-130`. Replace the `_get_client` if/elif with a table. `doctor.py` key/package checks are verbatim copies → two helpers over a list (290 → ~150). A native provider then costs ~90 lines instead of ~330. Keep module-level `AsyncOpenAI`/`AsyncAnthropic`/`RateLimitError` names and `_clients`/`_client` attrs (patched in tests). Note: a generic OpenAI-compatible endpoint already works today via `OPENAI_BASE_URL`; only its price is wrong unless `--local`.
5. **`Algorithm(StrEnum)` and a `ReasoningEffort` alias (small).** Algorithm strings are hand-written in ~15 places across cli, types, algorithms, checkpoint, cost, review. Keep the typer options as `str` (an enum option changes exit code 1 → 2 and the error text, which tests assert).
6. **Slim the processor layer (medium, mostly deletion, ~200 lines).** `DocumentContent.metadata` is never read in src; DOCX is parsed twice and text read twice to produce it. `detect_rtl` is duplicated in text.py and docx.py. `DocumentProcessor` Protocol and `BaseDocumentProcessor` ABC describe the same thing. `validate_file`/`supports_file_type`/page-range params unused. Risk: corrupt-PDF error message changes.

Rejected: a generic strategy loop across the three algorithms (their differences would become flags); typer enums; merging `TranslationResult` into `TranslationResponse` (would leak `glossary_updates` into JSON output, guarded by a test); a separate TranslateGemma class; estimating cost from loaded content (dry-run must not rasterise).

## C. Features (value / effort order)

1. **Prompt only when it matters; make `--max-cost` a real pre-flight check (S).** `cost.py:237` always adds a context-aware overhead warning and `:281` sets `requires_confirmation` for every cloud run, so the README quick start on a 7-word file stops at "Do you want to proceed?" and a non-TTY script fails. Prompt above a cost threshold only; refuse when estimate > `--max-cost` unless `--force`; never prompt when stdin is not a TTY.
2. **`--pages 1-3` for PDFs, and keep the checkpoint on partial failure (S).** `PdfProcessor.extract_content(start_page, end_page)` exists but nothing passes a range. Pairs with bug A2. Decide: real PDF page numbers in markers; output only the selected pages.
3. **Env defaults and a plan that names what will happen (S).** No typer option has `envvar=`; docs mention `TINBOX_MODEL` but nothing reads it. Plan table shows no model, endpoint, language pair or chunk count, and `doctor` does not report `OPENAI_BASE_URL`, so a stale oMLX base URL silently routes cloud requests to localhost. Add `TINBOX_MODEL`/`TINBOX_TO`/`TINBOX_FROM`, plan rows, doctor row. Recommend env vars only, no TOML yet.
4. **Per-model pricing, price override, richer output metadata (S–M).** Bug A5 plus: `TranslationMetadata` records `"model": "openai"` not the model name, no token split, no reasoning effort, no tinbox version; PDF estimate is a flat 500 tokens/page regardless of DPI (~2-3x low once image tokens count).
5. **Trustworthy glossary (S).** `--glossary-file` without `--glossary` is silently ignored (`cli.py:446-448`). `Glossary.extend` is last-write-wins, so the model can overwrite a curated entry mid-run. Make the file flags imply `--glossary` (or error); lock loaded entries.
6. **Survive long runs by default (M).** Retry bad model output (bad JSON, length stop, empty) N times; automatic checkpoints under a cache dir keyed by source hash + config (requires A1 first); "resuming 37/50" in the plan; cheap sanity warnings (translation identical to source, length ratio out of band). Decide: opt-out flag, since checkpoints hold document text; retry count; partial output on cost-cap stop.
7. **DOCX structure (S–M now, L later).** Step 1: `\n\n` joins, headings as `#`, lists, tables as Markdown rows (fixes A7). Step 2 (only on demand): write translations back into a copy of the .docx.
8. **Markdown-aware chunking (M).** `smart_text_split` will split inside a fenced code block and send both halves to be translated. For `.md` only: block-split first (front matter, fences, tables, headings), never split inside, pass fences through untranslated.
9. **`--pdf-text` opt-in text-layer extraction (M).** `pypdf` is already a dependency; born-digital PDFs could then use context-aware, glossary, review and text-only local models. Keep image as default (RTL/multi-column extraction is unreliable). Warn on empty text layers.
10. **`--concurrency N` for PDF pages (M, after C2 and C6).** Pages are independent and keyed by number already. Decide: glossary makes order matter (disallow or freeze); cap can overshoot by N requests. Not possible for context-aware text.

Rejected: live pricing fetch (offline/local use breaks; dated table + override covers it); batch/directory command (shell loop + env defaults + hash-keyed checkpoints covers it); stdin input; native Gemini/Mistral/OpenRouter SDKs (OpenAI-compatible path already works; honouring `OLLAMA_HOST` instead of hardcoded `localhost:11434` is a tiny follow-up); post-edit/back-translation passes; `tinbox models` (defer); `--verbose` (remove or alias to `--log-level DEBUG`); translated PDF output.

## D. Docs that over-promise

- `cli.md` says sliding-window uses ~1,000 chars with 100 context; real defaults are 2,000 / 200.
- `cli.md` language list omits `la` (added 0.5.1).
- `cli.md` says `--glossary-file` requires `--glossary`; nothing enforces it.
- README quick start does not say the run will prompt for confirmation.
- "Costs are approximate" undersells per-provider pricing and the DPI-blind PDF estimate.

## Suggested sequencing

1. Bugs A1, A2, A4 and feature C1 (all small, all first-run or money problems).
2. Refactors B1, B2, B3 (independent, no test rewrites beyond deletions and 4 asserts).
3. A5/C4 pricing together; then A3/C6 (partial output + retries), which depends on A1 making resume safe.
4. B5, B4, B6; then C2, C3, C5, C7 step 1, C8, C9, C10 as demand dictates.
